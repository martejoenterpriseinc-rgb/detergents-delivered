# Original customer receipt

The saved checkout status links to a household-protected original receipt at `/receipts/[checkoutId]`. Customers can reprint it or choose Save as PDF from their browser's print window. The document includes the order number, original purchase time in Central Time, original delivery address including unit, item/SKU/quantity/unit price, allocated savings, recorded item tax, promotion and reward totals, and original payment amount in USD.

The read-only service compares the immutable checkout snapshot with the saved order/items and a uniquely matching payment with verified checkout evidence. Pending, inconsistent, unsupported currency/shipping and unverified records fail closed. It supports verified zero-cash purchases. It never recalculates from current catalog prices, current customer addresses, tax rates or reward balances. It never calls a provider or changes an order, payment, reward or audit record. Reads use a repeatable database snapshot.

Receipts describe the original purchase, not the balance after later refunds. The document explicitly explains that later refunds and reward adjustments are separate. Sandbox purchases retain a visible test-receipt label even if subsequently viewed from a different connection mode. Print styles remove action links and buttons, retain the environment/test labels, and avoid splitting individual items across pages. React renders product/address text as text. Provider IDs, tax evidence, account email, private routing fields and current balances are excluded from the receipt DTO.

Authorization rechecks the current user, credential-change requirement, household and checkout ownership. Another household receives a not-found response. Deleted identities cannot retrieve receipts. The page is dynamic, authenticated and excluded from search indexing; it does not create a public PDF URL or upload a document to a third party.

Validation: native database tests cover original amounts, privacy, repeat reads, household isolation, deleted/credential-change users, pending/inconsistent/unverified records and a verified zero-cash purchase. Browser tests cover receipt navigation, refresh, printing, PDF generation, other-household denial, unchanged order/payment records, and desktop/tablet/mobile layouts. Fixtures are synthetic isolated database records. Full CI and screenshot results are recorded in the release PR. No migration or API setup is required for this increment.
