# Optional post-delivery tips

Customers can open **Optional delivery tip** from a delivered order, decline without a provider call, select a dollar amount, or select a percentage of the original merchandise total after discounts/rewards and before tax. The server validates original paid-sale evidence, owned order, confirmed delivery attempt and proof record. Tips are limited to $0.50–$500; percentage arithmetic uses integer cents. Declines are retained and may be followed by a later tip.

`DeliveryTip` is separate from Order/Payment/refund/reward records. The original order is never repriced or modified. A customer/order request key and payload hash, order lock and partial unique index prevent duplicate active or paid tips. Permanent request and settlement audits are transactional. Failed audit writes roll back local financial state; a verified provider payment can be reconciled again without another charge.

The separate hosted Checkout uses the original delivery-address snapshot, a dedicated customer, card payment, a pinned server amount and reviewed tip tax code, and automatic tax. The customer sees applicable tax before approving payment. Never assume tips have zero tax. Payment confirmation retrieves the session from the pinned account and matches customer, metadata, mode, currency, single line/product/tax code, subtotal, tax, total and succeeded PaymentIntent. No discount, shipping or original-sale payment can substitute for tip evidence.

Provider creation uses stable customer/session idempotency keys. The session expires after 60 minutes, and creation retries stop when less than 30 minutes remain; they do not replay old keys after Stripe's retention window. Unknown responses remain protected. Signed session webhooks recover a response lost before session identity was saved. Customer status checks and the existing payment-recovery worker retrieve known sessions without creating payments. An unknown session without a retained ID needs provider investigation; it is never treated as expired or paid merely because time passed.

Reports → Delivery tips is a private ADMIN/SUPER_ADMIN/CPA read-only gross-receipt report, bounded to 250 selected records. Paid totals require their matching API-reconciliation audit. Unconfirmed payments are excluded and counted for review. Driver attribution comes from the original tip snapshot. This report does not establish driver payouts, net deposits, refunded-tip balances or tax filing amounts. Tip refunds/payout accounting and QuickBooks mapping still require their own accepted workflow before production tipping is enabled.

Activation remains off. Setup at the owner's deferred API stage requires Stripe checkout readiness, `DD_TIPS_ENABLED=true`, a merchant-reviewed `DD_TIP_TAX_CODE`, and separate `DD_LIVE_TIPS_ACCEPTED=true` for production. Recovery remains available when collection is disabled. No provider account or hosted setting was changed during this build.

Migration: `20260917000000_delivery_tips`, additive only. Unit tests cover arithmetic, identity/amount/tax mismatch, fixed provider parameters, bounded retry and activation. Native PostgreSQL tests cover ownership/delivery, duplicate concurrency, separate financial records, decline, unknown response, CPA reporting and audit rollback. Browser tests exercise decline and interrupted saves at desktop/tablet/mobile widths with payment collection disabled. Provider adapters in automated tests are mocks and do not constitute Stripe acceptance.

Primary references checked September 12, 2026: [Checkout tax](https://docs.stripe.com/tax/checkout), [Checkout tax results](https://docs.stripe.com/tax/checkout/page). The configured code's legal/tax treatment and actual account behavior must be reviewed and accepted at provider setup.
